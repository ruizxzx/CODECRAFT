# OFFSCRPT V78.0.1 — Discussion 2.0 Runtime Hardening

## Scope
Unified conversation graph for posts, articles, questions, answers, communities and creators.

## Implemented
- First-class discussion model and `/discussion/:id` deep links
- Start Discussion, Article Discussion, Quote, Remix and multi-part threads
- Quote source snapshots and attribution
- Text-selection quote workflow on article pages
- Nested reply tree, parent/root navigation and unread state
- Realtime replies, reactions, followers and moderation state
- Rich reply composer with media, links, code, quotes, mentions and polls
- Discussion following and notification integration
- Article → Discussion and Question → Answer → Discussion entry points
- Thread navigator with numbered parts
- Discussion sorting and participant panel
- Author-response indicators
- Discussion search/related primitives
- AI discussion summary endpoint with grounded structured output
- Discussion analytics/read state foundations
- Firestore rules for community/root discussion replies, reactions and read state
- Backward-compatible existing posts/comments/replies

## Safety / compatibility
Existing V77 data remains readable. New discussion metadata is additive and guarded server-side/Firestore-side.


## V78.0.1 fixes
- Fixed `MentionTextarea is not defined` by adding the missing DiscussionPanel import.
- Removed duplicate `getCommunityProfile` import in ArticleView and repaired previously missing optimization imports.
- Community discussions now persist visibility, source metadata, discussion settings and poll data correctly.
- Discussion follow/unfollow now resolves root and community post locations correctly.
- Community thread navigation now reads both root and community thread parts.
- Added collection-group read access required by the all-community discussion feed.
- Public hero reader count now uses the public profile projection instead of private `users` aggregation.
- Added a real REMIX entry point on community discussions while respecting `allowRemixes`.
- Gemini discussion intelligence is retained and its API endpoint now verifies Firebase ID tokens server-side.
- All discussion runtime paths were rechecked for syntax, exports, identifiers, Firebase wiring and Firestore rule balance.
