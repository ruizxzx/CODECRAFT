# OFFSCRPT V75.2 — Main Article Comment Identity & Cloud Display Sync

## Changes
- Main article comments use the shared UserIdentity component.
- Real profile avatar/name/handle is resolved from the public profile directory when available.
- Clicking a comment identity opens the corresponding public profile route.
- Supports TOP, NEWEST, OLDEST, and MOST DISCUSSED comment sorting.
- Keeps Firestore realtime article-comment subscription as the source of truth.
- Comment identity enrichment treats stored comment metadata as fallback only.
- ArticleView wires its existing public-profile navigation into CommentsSection.

## Integrity
- Identity lookups never expose private UID/email fields to public viewers.
- Existing comment ownership continues to use authorId/UID.
- Profile/handle changes therefore do not sever comment ownership links.

## Site-wide consistency notes
- Main article comments continue to use the Firestore realtime `onSnapshot` source.
- Comment identity display is enriched from the public profile directory and falls back to the comment's stored public metadata.
- Clickable comment identities route through the same public-profile navigation used elsewhere in the article.
- The shared `UserIdentity` component never renders the internal Firebase UID.
- Canonical user ownership remains UID-based; display handles are mutable aliases.
