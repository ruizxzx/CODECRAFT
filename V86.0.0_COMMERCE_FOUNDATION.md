# OFFSCRPT V86.0.0 — Commerce Foundation

V86 establishes the first Creator Economy backend layer without enabling the full monetization suite.

## Implemented

- Canonical commerce product and price records.
- Server-authoritative order and payment lifecycle.
- Test-mode checkout and deterministic test payment confirmation.
- Purchase entitlements with centralized access resolution helper.
- Refund test flow with entitlement revocation and revenue reversal.
- Immutable creator revenue ledger foundation.
- Payout ledger schema foundation (no automated bank payout execution).
- Commerce audit events.
- API idempotency records and test-payment replay protection.
- Creator Studio Monetization tab.
- Creator product draft/activation workflow.
- Customer purchase history foundation.
- Commerce Firestore rules and indexes.

## Security

Firebase UID is the authoritative ownership identifier. Handles are only human-readable identifiers.
Financial mutations are server-side. The browser cannot set payment success, entitlement state, creator revenue, payout state, or checkout price totals.

## Server configuration

Required for deployed commerce mutations:

- `GOOGLE_CLOUD_PROJECT` (falls back to `VITE_FIREBASE_PROJECT_ID`)
- `GOOGLE_SERVICE_ACCOUNT_CLIENT_EMAIL`
- `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`
- `FIREBASE_WEB_API_KEY` (falls back to `VITE_FIREBASE_API_KEY`)
- `COMMERCE_PAYMENT_MODE=test` for deterministic test payments

Production payment provider credentials are intentionally not bundled. V86 does not claim live payments until a provider adapter and credentials are configured.

## Data lifecycle

Product → Price → Order → Payment → Entitlement → Creator Revenue

Refunds create a new refund record and revenue reversal. Original financial records are retained.

## Deployment note

The repository contains one canonical root `firestore.rules`. The rules and indexes must still be deployed separately to the Firebase project used by production.
