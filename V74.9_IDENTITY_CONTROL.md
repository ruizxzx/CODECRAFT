# OFFSCRPT V74.9 — Identity Control Hardening

## Identity behavior
- New Google accounts start with an unclaimed handle; display name is never silently reserved.
- Users can claim, change, or clear their own unique handle.
- Master admins can change or clear any user's handle from Master Control.
- Handle reservation changes are transactional and unique.
- Firebase UID remains the permanent internal identity key; handles are mutable public identity labels.
- Existing content/relationship documents retain UID ownership while denormalized visible identity is synchronized after the canonical change.

## UI fixes
- Removed duplicate Unique @Handle input from the public profile editor.
- Added a single handle editor to Master Control's user editor.
- Master user editor supports blank handle to unclaim and a new unique handle.

## Security
- Self profile updates are restricted to explicit profile fields.
- Privileged handle changes require Master Admin access.
- Username reservation writes validate the target UID against the post-write user document.
- Privileged handle changes are audited.
- UIDs are not displayed in public profile UI; Master Control may display the UID for administrator identity tracking.

## Deployment
Deploy both the frontend and the included `src/firestore.rules` to the corresponding Firebase project. Frontend deployment does not deploy Firestore rules.
