# OFFSCRPT V88.0.0 — Digital Product Engine

V88 extends V87 Creator Storefront with a server-authoritative digital-product and private-file foundation.

## Implemented
- Digital-product metadata stored on canonical `commerceProducts`
- Canonical `commercePrices` reused for pricing
- Vendor/creator ownership enforced by authenticated Firebase UID
- Product draft/edit/publish/archive lifecycle
- Product visibility: public, unlisted, private
- Product categories, tags, subtype, licensing metadata
- Real version records in `digitalProductVersions`
- Per-file metadata in `digitalProductFiles`
- Direct-to-R2 presigned uploads
- Private product storage via `R2_PRODUCT_BUCKET_NAME`
- Server-side upload verification using R2 HEAD
- File role and dangerous-extension validation
- File size and product-version limits
- File checksums (client SHA-256 plus R2 ETag metadata where available)
- Publish validation requiring a ready file and canonical price
- Product/version audit events
- Read-only admin diagnostics for orphan/version inconsistencies through future commerce tooling
- V87 storefront compatibility
- V86 commerce, test purchase, refund and entitlement compatibility

## Required storage configuration

Digital product files intentionally use a separate R2 bucket:

- `R2_ACCOUNT_ID`
- `R2_PRODUCT_BUCKET_NAME`
- `R2_ACCESS_KEY_ID`
- `R2_SECRET_ACCESS_KEY`
- `R2_S3_ENDPOINT` (optional when derived from account ID)

Do NOT use a public product bucket. The bucket should not have a public custom domain. Public media may continue using the existing `R2_BUCKET_NAME` / `R2_PUBLIC_BASE_URL` flow.

## Upload flow

1. Authenticated vendor requests an upload target.
2. Server validates vendor ownership, file type, size and product/version state.
3. Server generates a short-lived R2 presigned PUT URL.
4. Browser uploads directly to R2.
5. Server verifies the object with a short-lived signed HEAD request.
6. Server atomically creates file metadata and updates version counters.
7. Product can only be published when required files are ready.

## Important boundary

V88 creates the product-file security foundation. Full customer entitlement-based signed downloads are intentionally completed in V91.
