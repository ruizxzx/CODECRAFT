# V75.10 — Firestore Quota / Profile Media Fix

## What changed
- Normal authenticated self-profile edits now use a batched user + public-profile write without a preliminary Firestore read.
- Handle changes still use a transaction for atomic username reservation.
- Identity propagation no longer performs a mandatory post-save profile read.
- R2 media uploads remain independent of Firestore.
- Profile UI distinguishes Firestore quota exhaustion from actual media-upload failure.

## Important
A Firestore `resource-exhausted` / quota error is a Firebase project-level limit. Code optimization reduces avoidable reads/writes, but it cannot make a Firestore write succeed while the project's quota is exhausted.
