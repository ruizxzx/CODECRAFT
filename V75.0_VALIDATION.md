## Fixed runtime architecture
1. `publicProfiles/{handle}` is the public profile source and has `allow read: if true`.
2. Signed-out profile resolution does not read private `users/{uid}`.
3. Signed-in viewers may resolve a target UID only through the public handle reservation for authenticated operations; the UID is not placed in public profile documents or rendered as public profile data.
4. Profile activity can fall back to public username-indexed posts/comments when a private UID is intentionally unavailable.
5. Social Hub merges public directory people with prior message peers so a temporary public-directory failure does not erase existing message contacts.
6. Social Hub refreshes when the authenticated user changes, so People repopulates after sign-in.
7. New messages store recipient display metadata, allowing recovery of legacy conversation peers.
8. `firebase.json` maps Firestore rules to `src/firestore.rules` for explicit deployment.

## Live deployment requirement
If the browser still logs `Permission denied` for `publicProfiles`, the deployed Firebase Rules are older than this build. Vercel cannot change Firestore Rules. Deploy:
`firebase deploy --only firestore:rules`
