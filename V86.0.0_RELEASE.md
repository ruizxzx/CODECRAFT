# OFFSCRPT V86.0.0 — COMMERCE FOUNDATION + ENTITLEMENT ENGINE

## What changed

V86 establishes the first Creator Economy infrastructure layer while preserving V85.1.2 functionality.

### Commerce Foundation
- Canonical commerce product and price schema.
- Server-authoritative checkout/order/payment lifecycle.
- Explicit test-payment mode with no real charge.
- Immutable purchase snapshots.
- Central entitlement records and server-side `checkAccess` hook.
- Refund record + entitlement revocation + revenue reversal foundation.
- Creator revenue ledger.
- Payout ledger foundation without automated bank payout execution.
- Commerce audit and idempotency records.
- Creator Studio → Monetization foundation UI.
- Master Control → Commerce diagnostics.

### Regression fixes preserved / hardened
- Handle-based community invitation remains the user-facing identifier; Firebase UID remains authoritative internally.
- Community upvote/repost profile persistence now has explicit Firestore rules for `users/{uid}/upvotes` and `users/{uid}/reposts`.
- Root `firestore.rules` remains the single canonical rules file.
- Existing V85 scheduling, collaboration, Knowledge Engine, Discovery and analytics systems remain in place.

## Important deployment requirements

Deploy BOTH from the repository to the same Firebase project used by production:

- `firestore.rules`
- `firestore.indexes.json`

The source files do not automatically change an already deployed Firebase project.

For commerce server mutations, configure the documented server-only environment variables in `.env.example`.

V86 test mode is intentionally non-monetary. Live payment provider integration is deferred to the later Creator Economy build where provider/webhook configuration is introduced deliberately.
