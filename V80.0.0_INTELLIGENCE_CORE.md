# V80.0.0 — OFFSCRPT Intelligence Core

## Implemented
- Canonical ContentEntity compatibility/adapters for articles, posts/discussions, questions, answers, series, users and topics.
- Standardized private ActivityEvent stream with reading, engagement, discussion, question and search-result events wired into active flows.
- Central permission helpers and server-side Firestore-token-gated AI retrieval, including public/authenticated/follower/community/private/owner visibility handling.
- Shared content-relationship graph primitives and related-content derivation foundation.
- Unified in-memory search abstraction wired into the existing SearchModal without removing its existing tabs/data sources, including date/type/creator/topic/tag/community/series and reading-time filter seams.
- Shared generic RecommendationEngine foundation for heterogeneous content.
- Reading Intelligence derivation from existing reading history/progress/search behavior.
- Master-controlled Intelligence feature flags in `intelligenceConfig/global`; AI retrieval is rechecked server-side by the gateway.
- Index-sync queue foundation attached to article lifecycle create/update/publish/unpublish/delete paths.
- Standardized activity health diagnostics in Master Control.
- V80 schema blueprint and Firestore rules for activity events, graph edges and intelligence flags.
- OpenRouter gateway retained; OFFSCRPT server retrieval is inserted before OpenRouter generation and source IDs are preserved.
- Semantic retrieval seam with chunking, embedding-provider interface, and hybrid-score merge logic; no vector backend is silently invented.

## Foundation-only / not falsely promoted to complete
- A durable worker for draining `indexSyncQueue` and updating an external search/vector index is not included; queue + lifecycle hooks are the foundation.
- `semanticSearch` is a feature flag/architecture seam only; no production vector database or embedding worker is provisioned.
- The generic RecommendationEngine exists, but every legacy feed surface has not yet been migrated to a server-ranked cross-content recommendation API.
- Full cross-content persisted graph backfill is not performed; relationship utilities and derived related-content logic are present.
- AI conversation history remains localStorage as in V79.11.
- Full production build depends on installing the existing dependency tree; this environment previously lacked `node_modules` and may not have network access.

## Compatibility
Existing V77/V78/V79 collections and IDs are preserved. No destructive database migration is required.
