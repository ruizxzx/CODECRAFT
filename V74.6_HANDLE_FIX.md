# OFFSCRPT V74.6 — Identity / Unique Handle Integrity

- Google display names no longer auto-claim the global @handle namespace for newly created community profiles.
- New profiles are created with `username: ""` and no `usernames/{handle}` reservation.
- The claim modal starts blank for ordinary users; only the configured canonical admin accounts retain their fixed canonical handle.
- First-time handle claiming works even though the profile already exists, using an atomic Firestore transaction.
- Profile Settings now exposes display name + unique @handle editing, with availability checks and Firestore-backed atomic reservation/release.
- Users may clear their handle; the old reservation is released.
- Master/content profile synchronization receives the new handle value.
- People/creator discovery continues to exclude profiles with no claimed handle.
- Firestore rules bind username reservation create/update/delete to the same user-profile transaction so users cannot reserve arbitrary extra handles.
