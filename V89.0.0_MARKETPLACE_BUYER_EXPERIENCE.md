# OFFSCRPT V89.0.0 — Marketplace + Buyer Experience

## Scope
V89 extends the V86 Commerce Foundation, V87 Creator Storefront, and V88 Digital Product / Purchases architecture into a public digital-product marketplace.

## Routes
- `#shop` — canonical marketplace landing/discovery route
- `#marketplace` — compatibility alias
- `#shop?q=...` — URL-addressable product search
- `#shop/category/<category>` — category discovery
- `#saved-products` — buyer saved-products library
- `#wishlist` — saved-products compatibility alias
- `#product/<productId>` — product detail route
- `/product/<productId>` — supported direct product URL for refresh/SEO compatibility

## Canonical data
Products continue to live in `commerceProducts`. Prices continue to live in `commercePrices`. Purchases and access continue through the existing `commerceOrders`, `commercePayments`, and `entitlements` collections. No duplicate marketplace product collection was introduced.

## Public discovery security
Only `status=active` and `visibility=public` products are returned by marketplace discovery and public product projections. Private downloadable R2 objects are never used as public previews and product storage credentials are never exposed to browser code.

## Marketplace experience
- Featured, trending, newest, and popular-creator sections are data driven.
- Search covers title, subtitle, description, category, subcategory, tags, and creator identity metadata.
- Search is normalized, debounced, URL-addressable, and cursor paginated over a bounded public catalog window.
- Filters cover category, type, creator, and price bucket; sort supports relevance, newest, popular, low price, and high price.
- Creator/storefront product cards use the existing V88 thumbnail/gallery preview data.
- Product cards show real price, product type, cover preview, save state, and owned state.

## Buyer features
- `savedProducts` uses `users/{uid}/savedProducts/{productId}` and stores only product references plus timestamps.
- Saved products are private to the owning Firebase UID.
- Product pages resolve purchase state from canonical entitlements rather than local-only state.
- Owned products link to the existing My Purchases / secure-download flow.
- Unauthenticated Save/Buy/My Purchases/Saved Products actions gate through the existing Google sign-in flow.

## Product detail experience
- Responsive two-column desktop layout and single-column mobile layout.
- Public gallery with thumbnail strip, previous/next controls, image count, fullscreen viewer, keyboard Escape/arrow controls, and focus restoration.
- Breadcrumbs, creator information, related products, more-from-creator, share, copy-link, license, requirements, usage, and included-content sections when stored.
- Product metadata is projected from the server into a safe public shape.
- Product detail document title, description meta, and canonical URL are updated for the active product.

## Discovery / analytics
Marketplace events use the existing activity architecture. Added event types include:
`marketplace_view`, `marketplace_search`, `marketplace_filter`, `product_impression`, `product_open`, `product_gallery_open`, `product_gallery_next`, `product_save`, `product_unsave`, `creator_store_open`, `category_open`, `related_product_open`.

Product-card impressions use `IntersectionObserver` and are emitted once per mounted card when the card enters the viewport threshold. Search request sequencing prevents stale responses from overwriting newer queries.

## Performance
- Marketplace API results are bounded.
- Product lists use explicit limits and cursor tokens.
- Product cards load one public cover image instead of a full gallery.
- Creator identity is represented in marketplace summaries so discovery does not need one creator query per card.
- Buyer ownership and saved-product state are batched at page scope.
- Search input uses a short debounce and stale-request protection.

## Firestore / indexes
`firestore.indexes.json` declares the marketplace `commerceProducts` status/visibility/publishedAt index. Existing collection-group identity indexes are preserved.

## R2 boundary
Public product gallery/cover images continue to use the existing public media R2 system. Paid downloadable files continue to use the dedicated private product R2 configuration and existing V88.7 secure download/signing path.

## Compatibility boundaries
V89 does not implement live payment providers, payment webhooks, full advanced order delivery, vendor onboarding, commissions, balances/payouts, admin finance, reviews/moderation, coupons, affiliate systems, or final launch hardening. It leaves compatibility hooks for V90–V97.

## Known limitation
The marketplace discovery API reads a bounded public-catalog window before applying in-memory relevance/trend/secondary filters. This prevents unrestricted client collection scans and keeps the Hobby-plan deployment bounded, but a future dedicated search/index service may be required for catalogs substantially larger than the current bounded window.

## Security / regression checks
- No alternate marketplace product source.
- No `/api/lib` shared utilities.
- No browser R2 secret access.
- Stable React hook order in marketplace/product components.
- Public/private/unlisted discovery boundaries enforced.
- Saved-product rules bind reads/writes to `request.auth.uid`.
- Existing V88 purchase and secure-download paths remain canonical.
