# OFFSCRPT V89.0.1 — Marketplace Index Hotfix

## Production issue fixed
The V89 marketplace API was returning HTTP 500 because Firestore reported `FAILED_PRECONDITION` for a `commerceProducts` status + visibility + publishedAt composite query when the required index was not present in the deployed Firestore database.

## Fix
Marketplace discovery now uses a bounded `status == active` query with deterministic `__name__` ordering and a limit of 300. `visibility == public` plus creator/category/subcategory/type filters are enforced server-side. This removes the runtime dependency on the missing composite index for the marketplace path.

The original `status + visibility + publishedAt` index is retained and a collection-group compatibility index is declared in `firestore.indexes.json` for environments that use a collection-group query.

## Security
Only products whose stored status is `active` and visibility is `public` are projected into marketplace discovery results. Private, unlisted, draft, archived, and disabled products are excluded before response projection.

## Scope
No payment, order, payout, moderation, vendor, R2 credential, or V88 purchase/download architecture was replaced. V88.7 secure download signing remains canonical.

## Validation
The repository's static marketplace validation, syntax parsing, Firebase/rules/schema/runtime/Commerce/storefront/digital-product/R2-signing/deployment/path checks pass in this environment. A full `npm ci` + dependency-backed build could not be completed because the execution environment timed out during dependency installation; this is recorded rather than reported as a pass.
