# V74.9 — Public Profile + Handle Route Integrity

- Public claimed profiles are served from `publicProfiles/{handle}` so logged-out visitors can open `/\#@handle`.
- Public profile documents contain presentation/identity data only; they do not contain Firebase UID, email, moderation flags, or admin/security fields.
- Private `users/{uid}` reads remain restricted to the account owner/master admin.
- Signed-in users may internally resolve a target UID through the handle reservation for existing follow/activity operations; the UID is never rendered.
- Existing and new handle claims create/update the public projection. Handle changes atomically replace the public handle projection and reservation.
- Profile edits update App-level user state and close the claim modal immediately.
- Successful handle changes navigate to the new public handle route; clearing a handle returns to Settings.
- People discovery uses claimed public profiles only; unclaimed accounts remain absent.
