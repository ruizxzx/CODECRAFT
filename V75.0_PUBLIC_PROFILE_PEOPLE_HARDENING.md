# OFFSCRPT V75.0 — Public Profiles + People Directory Hardening

## Changes
- Public profile resolution remains based on `publicProfiles/{handle}` and does not require a viewer to read private `users/{uid}`.
- Signed-in viewers no longer query the public username reservation merely to render another person's profile.
- Existing claimed profiles can be rebuilt by Master Admin into `publicProfiles`.
- Profile-owned public posts and comments can resolve by public handle when private UID identity is intentionally unavailable.
- Messages now retain recipient display metadata so a signed-in user can recover prior message peers even if the public people directory is temporarily unavailable.
- Social Hub merges public-profile people with prior message peers, preventing the People list from disappearing completely during a public-directory permission outage.
- Added `firebase.json` and `.firebaserc` so the included Firestore rules have an explicit deployment target.
- `publicProfiles/{username}` is intentionally `allow read: if true` because the document contains only public presentation data.

## Critical deployment requirement
The live Firebase rules must be deployed. Vercel cannot change Firestore authorization rules. Run:
`firebase deploy --only firestore:rules`
from the project root after authenticating the Firebase CLI.

## Identity
Firebase UID is the immutable internal identity key. Handle is a mutable public alias. Do not put UID, email, roles, or moderation fields into `publicProfiles`.
