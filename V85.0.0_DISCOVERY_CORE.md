# OFFSCRPT V85.0.0 — Discovery Core

## Purpose
V85 turns the existing search and recommendation foundation into one shared discovery layer without creating a parallel content store.

## Implemented
- Universal search query planning with inline filters: `type:`, `topic:`, `tag:`, `author:`/`from:`, `community:`, `series:`, `before:`, `after:`.
- Shared search scoring using lexical relevance, title matching, topic/tag relevance, freshness and engagement.
- Shared discovery scoring primitives for freshness, engagement, quality, trends and diversity.
- Deterministic discovery facets for content types, topics and tags.
- Existing permission filtering remains before ranking/results.
- Existing SearchModal, Explore and recommendation systems remain backward compatible and can consume the improved unified ranking primitives.

## Foundation preserved
- Firestore remains the canonical data source.
- Existing routes and existing content adapters remain unchanged.
- V84 Knowledge Engine and provider abstraction remain intact.
- Existing personalized feed/preferences remain intact.

## Not implemented in this release
- External dedicated search service deployment.
- Dedicated vector database deployment.
- Full offline index replication.
- Autonomous AI recommendations.

## Validation
See `BUILD_VALIDATION_V85.txt`. Any unavailable dependency-backed checks must remain marked BLOCKED rather than PASS.
