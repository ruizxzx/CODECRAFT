# OFFSCRPT V75.0 — Public Profile Access + Identity Routing Hardening

## Fixed
- Public profile reads never require signed-in access to private `users/{uid}` documents.
- Signed-in viewers no longer read `usernames/{handle}` merely to render another person's profile.
- Existing profiles without a UID-bearing public projection can still render public presentation and username-indexed public content.
- Profile comments can resolve by `authorUsername` when a private UID is intentionally unavailable.
- Messages/People continues to source public people from `publicProfiles`, excluding unclaimed accounts.
- The public profile route remains `/#@handle`.

## Critical deployment requirement
The Firebase project must deploy the included `src/firestore.rules`. Its `publicProfiles/{username}` read rule is intentionally public because the collection contains only public presentation fields. The app cannot override an older deployed ruleset.

## Identity model
- Firebase UID remains the immutable private identity key.
- Handle is a mutable public alias.
- Public profile data is stored separately from private account data.
