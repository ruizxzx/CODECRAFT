# V89.0.1 — Marketplace Index Hotfix

## Problem
Marketplace API queries were failing in production with Firestore `FAILED_PRECONDITION` because the deployed Firestore database did not have the requested `commerceProducts` composite index.

## Fix
The marketplace discovery read path now uses a bounded `status == active` query ordered by document name, then enforces `visibility == public` and marketplace filters server-side. This removes the immediate dependency on the status/visibility/publishedAt composite index for marketplace availability.

A collection-group compatibility index matching the previous marketplace composite query is also declared in `firestore.indexes.json` for environments that use collection-group discovery paths.

## Security
Only products whose stored status is `active` and visibility is `public` are projected into marketplace results. Secondary filters are applied server-side; private/unlisted/draft/archived/disabled products are excluded.

## Scope
No payment, order, payout, moderation, or vendor systems are changed. Existing V88 purchase/download flows remain canonical.
